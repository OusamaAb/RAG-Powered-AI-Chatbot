# Work So Far — 2026-05-13

This document summarizes the RAG-powered portfolio chatbot work completed so far. The project goal is to add a chatbot to Ousama's portfolio website that answers recruiter-style questions using only the approved Markdown content inside `portfolio-knowledge/`.

## Goal

The chatbot is being built as a retrieval-augmented generation system. Instead of letting the model answer from general knowledge, the backend retrieves relevant portfolio chunks from Supabase and sends only those chunks to the model. If the portfolio content does not contain enough information, the chatbot should say:

> I don't have enough information about that from Ousama's portfolio content.

The intended questions include topics like Ousama's projects, full-stack experience, backend experience, AI and machine learning work, Ministry of Transportation internship, technical skills, and why he is a strong candidate.

## Knowledge Base

The approved source of truth is the `portfolio-knowledge/` folder. It contains Markdown files for:

- general background: `about-me.md`, `resume.md`, `skills.md`, `faq.md`
- projects: BreakEven, NAO Robot, Document Scanner, Smart Parking System, Football Pickems
- experience: Ministry of Transportation Ontario and Vanguard
- coursework: cloud, databases, embedded systems, testing, networks, security, computer vision, algorithms, and intelligent systems

The knowledge files were cleaned up so placeholder sections no longer get embedded. The ingestion preview now reads 23 Markdown files and creates 321 chunks with no placeholder warnings.

## Supabase Vector Database

We created the Supabase migration:

`supabase/migrations/20260512000000_create_portfolio_chunks.sql`

That migration adds the `portfolio_chunks` table with:

- `id`
- `content`
- `embedding`
- `source_file`
- `project_name`
- `section_title`
- `chunk_index`
- `metadata`
- `created_at`

The embedding column uses `vector(1536)` for OpenAI `text-embedding-3-small`.

The migration also enables pgvector, adds an HNSW cosine index, enables row-level security, and creates the `match_portfolio_chunks` RPC function for similarity search.

We also added:

`supabase/migrations/20260512001000_grant_portfolio_chunks_service_role.sql`

That grant migration gives only the Supabase `service_role` permission to read/write the private vector table and execute the matching function. Public anon/authenticated access remains revoked.

## Ingestion Script

We created:

`scripts/ingest-portfolio-knowledge.mjs`

The script can:

- read only `portfolio-knowledge/**/*.md`
- split Markdown by headings and chunk size
- attach metadata such as source file, project/topic name, section title, chunk index, category, title, and character count
- skip placeholder-only sections
- preview chunks without calling external services
- generate embeddings through OpenAI
- clear and replace rows in Supabase `portfolio_chunks`

Useful commands:

```bash
node scripts/ingest-portfolio-knowledge.mjs
node scripts/ingest-portfolio-knowledge.mjs --upload
```

The upload path successfully embedded and stored the portfolio chunks in Supabase.

## API Route

We created:

`api/chat.js`

The route accepts:

```json
{
  "message": "Tell me about Ousama's projects"
}
```

The API flow now does the following:

1. Validates the request.
2. Handles greetings and goodbyes directly.
3. Embeds the user question using OpenAI `text-embedding-3-small`.
4. Calls Supabase `match_portfolio_chunks`.
5. Builds a context block from the retrieved chunks.
6. Sends the context and question to the OpenAI Responses API.
7. Returns a grounded answer plus `matches` and `sources`.

The API also includes guardrails:

- only use retrieved portfolio context
- do not invent missing details
- fall back when no relevant information is found
- keep answers simple and short
- avoid mid-sentence cutoffs by post-processing overly long answers into complete sentences or complete bullets

## Behavior Improvements

Several tuning passes were made after testing the chatbot:

- Generic questions like "Tell me a bit about Ousama" now bias retrieval toward `about-me.md`.
- Answers are now plain and concise.
- Greetings like "hello" return a personal assistant-style response.
- Goodbyes like "thanks bye" return a natural closing response.
- Long answers are post-processed so they do not cut off midway.
- Unsupported personal questions, such as favorite movie, correctly return the fallback.

Example working questions:

- Tell me a bit about Ousama.
- What did Ousama do at the Ministry of Transportation?
- Why is Ousama a strong software engineering candidate?
- What is his strongest full-stack project?
- List his strongest projects.
